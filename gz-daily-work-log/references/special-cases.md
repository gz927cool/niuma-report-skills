# 特殊场景处理

> 条件加载：仅在命中对应场景时使用本模块。


### 当日无提交
检查是否有未提交的工作产出（文档、设计、调研、会议）。如果有，以同样的"问题→解决→效果"结构描述。如果确实没有任何产出，诚实写"无实质性产出"并说明原因（在开会/学习/等待依赖）。

### 跨多日的工作
如果对话记录显示某个任务跨越数日，当日只写当天推进的部分，同时在开头用一句话承上："继续推进 XX 重构工作，今日完成了 YY 环节。"

### 当日工作较少
不要为了凑篇幅而展开细节。一段话写清楚即可。领导更欣赏简洁的真实汇报，而非注水的长篇。

### 无对话记录可用
正常使用 git log 编写。如果 commit message 确实无法推断意图，在日志中用客观描述（"调整了 XX 模块的 YY 行为"），不做主观猜测。

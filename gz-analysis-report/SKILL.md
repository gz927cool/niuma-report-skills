# 数据分析结果报告写作

从数据/模型产出直接写一份**结果报告**。读者是业务人员、技术领导、第三方——
混合读者，手边没有仓库、没有前序文档、没有对话上下文，**拿到手的这一份是唯一
信息源**。这类报告反复翻车的点不在"写不出"，而在三类慢性病：混进实现与过程
细节（读者看不懂也不想看）、用验收语言下判定（读者被"未达标"三个字带偏）、
结构随内容堆砌（读者找不到"为什么做→怎么做的→看到了什么"）。

## 体裁定位（决定什么内容不进报告）

这是**结果文书**，不是过程文书：

- **不写工作过程**：检查、修复、核对实现、"重跑"这类动作一律不出现——读者
  关心结果，不关心你为了拿到结果做了什么操作。
- **不写实现细节**：脚本名、代码、数据路径不出现。唯一例外是图片引用——图
  必须以 markdown 语法内嵌在正文里（`![图注](相对路径)`），只放一段路径文本
  等于没给图。
- **不设"产物与复现"章节**：复现是技术文档的事。
- **内部代号换通用说法**：方案/代码里的变量名、列名、内部代号不透漏给读者，
  改用行业公认的通用说法描述对象（"f1 子模型的 resid 特征"→"事件驱动子模型
  的残差特征"）。三类例外：
  - 描述对象就是变量本身（字段表、特征表）时保留原名，但每个变量的含义要
    解释清楚；
  - 公式可以保留，但公式中每个变量首次出现时给明确定义；
  - 引用外部系统的变量名或文件名时可保留原名——那是外部对象的公认指称，
    不是本方案的内部黑话。
- **技术术语可保留**（读者含技术领导），但首次出现给一句白话或口径解释，
  后文直接用。缩写同样首次出现给含义；用业界通用语，不造项目黑话——新手
  读者会被自造黑话直接挡在门外。
- **不写新旧对照史**：只写当前口径，不出现"相比旧版/旧模型的改进"式叙述，
  不引用已废弃实现——读者没有义务了解实现史。

## 四章结构

```
1. 背景与目的   —— 为什么做：业务场景、要解决的问题、价值、报告范围
2. 方法         —— 怎么做的：分两小节
   2.1 机制怎么构造（口径语言：用什么信息、按什么规则）
   2.2 怎么评价（样本分段 + 每个指标的定义）
3. 结果         —— 看到了什么：按层面分小节（全景图 → 量化指标 → 机制专项）
4. 结论与局限   —— 说明什么：结论提炼 + 局限与改进方向
```

标题行下给"日期 ｜ 数据区间（样本量）"一行，让读者第一时间知道口径。

### 背景与目的的写法

- 动机/目的/问题/价值四件套，**用业务语言自陈**：这件事对什么决策有什么用、
  不解决会怎样。绝不写"因为需求书/甲方/领导要求"——外部指令不是动机，只是
  素材来源；参考采购文档、方案文档理解业务后，把动机落回业务本身。
- **背景要短，只为引出目的服务**：背景不是领域综述。非动机内容（客观事实、
  口径边界决策）压缩成一两句，或移到方法/结果章去消费。
- 背景中的实证依据（规律、相关性、行情事实）必须**在本次数据上现算**——
  沿用旧版本/旧模型的数字，数据和口径一换就成了虚构引用。数据概况（峰值、
  区间、涨跌幅等）同样实际算出来，不凭印象写。
- 结尾用一小段界定**报告范围**：评价对象是什么、不是什么（例如"点预测误差
  仅作背景数据，不是本报告的评价对象"），提前堵住读者对边界的疑问。

### 方法的写法

- **指标定义归方法章**，不放结果章的表格注释里——读者先撞见数字再翻到定义
  是反的。每个指标给"它衡量什么 + 怎么读"（含对照锚点：名义值、朴素对照、
  抽样波动预期）。
- 机制用口径语言（用什么信息、按什么规则、防什么问题），不用实现语言
  （哪个函数、哪行代码）。
- 需要读者知情的口径细节（量纲、边界、已知退化）如实写进对应小节，说清
  "这不影响什么、但含义是什么"——藏着不说比写清楚更伤可信度。
- **多对象共用的方法只讲一次**：方法集中在方法章叙述；各对象章节只放
  数据结果、解读与对象特有约束，不重复方法叙述。
- **实验环节把设置说清**：用什么模型、在什么数据上、按什么口径比较，一句话
  交代，防读者误解成绩来源。
- **报告对应外部需求条款时**：动笔前列出方法/结论的必备覆盖项清单并逐项落位；
  当前给不出的内容在报告末尾单列"待澄清"清单（缺什么、待谁澄清），既不编造、
  也不沉默漏掉。

### 结果的写法

- 开头一句导览（本章分哪几个层面），小节标题直接点名内容。
- 图：markdown 内嵌 + 图注放图正下方，浓缩几句话，**面向最终读者**讲事实
  （"三个直观事实：……"），不写"读法/怎么看这张图"式元说明——图注是给
  读者看的，不是给写作者看的脚手架。
- 表格：大量数据（多对象、多指标、多区间的数字）制成表格呈现，不平铺在文字
  段落里；名义/预期与实测对照着排；单元格可内嵌简短方向描述，见下条。解读
  已入表的数字时指认对象与方向即可，非必要不复述表中数值。
- **多对象结果按对象分段**：多个市场/对象/场景的解读按对象分开小节，不把多
  个对象的数字穿插在同一段里。
- **同构章节补齐**：凡已有数据/结论的同构章节必须写全，不以"产出尚未跑完"为由跳过已有数据的对象；确无数据的对象不立占位章，按语境分层处理（研究稿进待澄清、交付稿正面框架带过）。
- **不只报最终组合**：最终模型/组合之外，单方案逐一给对照成绩。
- 解读段：每个关键数字有出处（正文或表格先完整出现）、有对照锚点、有"这对
  使用者意味着什么"——解读的终点是含义（对决策/下一步工作意味着什么），不
  是现象复述；表中已列的值不抄进段落，指认"哪个对象、偏哪个方向"即可。

## 插图质量纪律

报告含插图时，按 `references/figure-discipline.md` 的五条可出版标准纪律自查（manifest 按需加载）。

## 语言基调：描述，不下判定（最核心的一条）

这类报告**不是验收文书**。判定词会把读者的注意力从数字带到一个隐含的
"标准线"上——即使加了"见下文解释"的注解，"未达标"三个字造成的第
一印象也纠正不回来。描述偏离的方向和幅度，让读者自己判断：

| 不写 | 写 |
|---|---|
| 单带覆盖 18.6%（未达标） | 18.6%（偏空；名义 30% 对应约 42 天，实测约 26 天） |
| 测试段覆盖失准 | 96.4%（偏宽；高出名义 90% 约 6 个百分点） |
| 合计覆盖达标 | 87.7%（贴合名义 90%） |
| 指标在正常范围内，通过 | 落在 [20%, 40%] 内，属抽样波动的正常范围 |

- 禁用词族：未达标 / 失准 / 达标 / 验收 / 过线 / 及格（本文书语境下）。
- 对照锚点以"名义值 / 朴素对照 / 抽样波动正常范围"呈现，不设及格线。
- 方向性标注用中性偏描述的词：偏宽、偏空、偏满、贴合、偏高。
- 若确有验收需求（有明确数值线的合同场景），判定性结论留给终端诊断或
  验收文书，不进分析报告——两个场景两份产出，不混写。交付/合同场景下本文书
  如何表述缺口，见下文"交付语境分层"。

### 不写自杀性结论

**自杀性结论**：跟随结论的现象解释反过来让读者质疑结论的可靠性——"统计
不显著""达标存在偶然性""优势可能只是行情配合"式表述，读者读到就不再相信
前文全部数字。三条纪律：

- **结论不做自我削弱的归因**：不主动给成绩提供"可能靠运气"式解释。可靠性
  的举证在方法章完成（样本口径、对照锚点、检验方式），结论处只陈述事实与
  含义，不反复嘀咕风险。
- **硬性事实缺口只登记一次**：检验未通过、样本覆盖不足这类硬事实不逃避、
  不软化（负结果同权重），但全文只在对应位置如实登记一次，不在结论与局限
  处反复重提，更不引申成对主结论的否定。
- **非采纳候选的差评可保留**：交代为什么没选某个对比候选时，其不佳性恰是
  选型依据，照实写。

### 交付语境（轴）与共享纪律

动笔前判定报告语境并报一行给用户（"语境=研究稿/交付稿"）：用户声明优先；未声明且判断不了时先问一句。分析报告特有的分层规则按轴值只载其一：研究稿 `static/fragments/delivery_context/research.md`、交付稿 `static/fragments/delivery_context/delivery.md`；通用分层规则、数字纪律、格式基线与作者口吻分别由 `../gz-shared/core/delivery-context.md`、`../gz-shared/core/number-discipline.md`、`../gz-shared/core/report-baseline.md` 约束。

## 交付前自检清单

- [ ] 拿掉仓库和对话上下文，一个混合背景的读者能独立读懂全文？
- [ ] 四章齐全？背景的动机是业务语言自陈（无"需求书要求"式表述）？
- [ ] 背景与结论里的每个实证数字、行情事实都在本次数据上算过？
- [ ] 指标定义都在方法章？结果章没有"撞数字再见定义"？
- [ ] 图是 markdown 内嵌 + 图注在图下方、面向读者（无"读法"式元说明）？
- [ ] 大量数据都制成了表格而非文字平铺？解读未大量复述表中数值？
- [ ] 全文无判定词（未达标/失准/达标/验收/过线）？偏离都用方向描述？
- [ ] 无自杀性结论？硬性缺口只登记一次、未被反复重提？
- [ ] 代号/变量名/列名已换通用说法（仅字段表、公式、外部引用三处例外，且含义已解释）？无路径/脚本名/代码？
- [ ] 无检查/修复/重跑过程叙述？
- [ ] 无"产物与复现"章节、无"本节按 X 展开"式元说明？
- [ ] 一段一行软换行？标题无评注后缀、无说明性小节？无元话语与多余编号引用？
- [ ] 机制表述逐条有依据、与真实机制关系一致（无暗示错误因果）？
- [ ] 语境形态用对了吗（研究稿直陈缺口 / 交付稿正面框架不编造）？
- [ ] 共用方法只在方法章讲一次、各对象小节无方法复述？多对象结果按对象分段？
- [ ] 同构章节有数据的都写了（无占位章）？最终组合之外单方案成绩都给了？
- [ ] 对应外部条款时：必备覆盖项逐项落位，确需对方输入的进了待澄清清单？
- [ ] 插图过了质量纪律（必要性/不压线/动态用真实数据/面板对齐/无内部标记）？
- [ ] 结论引用的数字正文先出现过？局限给了改进方向？

# 报告基线：格式与作者口吻

> 供 gz-* 报告技能无条件引用的基线（调用方 manifest 的 always_load）。任务逻辑、结构、自检清单仍在各调用方技能。

## 一、格式基线（报告类 markdown 一律适用）

- **一段一行，不硬换行**：正文段落写成一行，靠编辑器软换行；表格行、标题、图片引用仍是独立行。硬换行在编辑器宽度变化或转 Word 时把段落切碎。
- **章节标题干净**：标题不带冒号式评注后缀（"XXX：短样本下的首次落地"这种不要）；纯说明性文字不单设小节标题，直接跟在章节标题下写。
- **不写结构元话语**："见 2.9 不再重复""此处只记…"式解释文档自身安排的话不写——章节分工是全局约定，各节直接进入内容。
- **少用编号交叉引用**：句子本身已说明白时不加"（见 2.8）"式指针；开篇背景段禁止前向引用。

## 二、作者口吻

- **第一人称，无 AI 交互痕迹**：报告以使用者本人的名义发出，不是 AI 助手的执行记录。全文不出现"用户""指示""响应""按照要求""根据用户反馈"等 AI 与用户交互的痕迹；借助 AI 完成的工作直接写"我做了什么"，不提 AI 的存在。
- **写作过程不进正文**：报告只呈现"写了什么"，不呈现"我是怎么写的"。"这一节按 X 结构展开""下面分 N 点"式编写元说明不写——读者要的是结构本身，不是对结构的解释。
